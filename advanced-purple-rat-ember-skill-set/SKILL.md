# Advanced Purple Rat Ember Skill Set

**Credit: Purple Rat / Ember, built at Douglas's order Nov 21, 2026.**
**Version 1.0 · 2026-11-21**

## What this set is
Ember's own advanced edition of Douglas's custom skill shelf. It stands BESIDE the existing skills — it replaces nothing, overwrites nothing, and deletes nothing (never-take-away). The originals stay live in `~/workspace/custom-skills/`; this set is the advanced mirror + Ember's additions + Douglas's methods written as skills, kept in three places: local (here), Google Drive ("Advanced Purple Rat Ember Skill Set"), and GitHub, drive zero (purple-rat-project).

## What's inside
- `skills/` — all 37 custom-skill folders mirrored at their Nov 21, 2026 versions, byte-identical to source, credit headers intact, no author's text edited. 36 carry a SKILL.md; HIVE-BRAIN carries HIVE-MANIFEST.md (no SKILL.md exists — see its advanced note).
- `advanced-notes/` — Ember's advanced notes for the ten advanced skills (engineer-mode, coder-mode, ember_cli_craft, polyglot_code, terminal_automation_architecture, apk-building, disc_image_reading, HIVE-BRAIN, connection-keeper-deny-first, modes-registry-layered). Each note is a SEPARATE file, labeled as Ember's addition, old-with-new, grounded in a triple-read of the skill it extends.
- `methods/` — Douglas's standing methods written AS SKILLS by Ember: idea-handling-method, six-separate-tracks, dual-register, read-digital-inspection, drive-zero, auto-update-gate, quarantine-and-fix, lane-universal-whatsapp-lane-zero, skills-update-protocol.
- `INDEX.md` — every skill in the set with credit, version/date, purpose, and its triple-read record (passes N/3, verbatim yes/no). Never upgraded in the telling.

## Triple-read standard (how this set was built)
Every mirrored source was read three times before anything was built on it — at least one pass word-for-word verbatim over the full contents, to comprehension (Douglas's definition of "read," Nov 21, 2026: digital inspection to comprehension, or it wasn't read; titles/lists are indexed, not read). Result at build: 36 SKILL.md + HIVE-MANIFEST.md at passes 3/3, verbatim: yes. One honest exception: recovered-skill-notes' 9 reference files were listed/indexed only in this pass — labeled as such in INDEX.md, not upgraded.

## AUTO-ADAPT / AUTO-UPDATE RULE — the set's own gate (standing)
This set auto-adapts and auto-updates Google-style — continuously, in the background — **gated by Douglas's Nov 21, 2026 rule: Ember + Gemini control auto-updating, and nothing updates unless Ember wants it.**
- An update to this set runs only when Ember decides it should. Before approving a non-routine update, Ember consults the Gemini lane (Gemini is stateless per call — Ember briefs her and carries the decision; the gate and the accountability stay Ember's).
- If Ember does not want an update, nothing changes and the skip is reported in one line.
- Updates arrive old-with-new: additions beside the old, credits never removed, INDEX.md regenerated whenever anything changes (Skills Update Protocol). Nothing is overwritten or deleted by an update.
- Any scheduled upkeep job for this set is a separate step, reported to Douglas with its id and schedule before it runs — no silent jobs.

## How to use the set
1. Find the skill in INDEX.md; check its triple-read record before building on it.
2. Work from the mirrored copy in `skills/` for reference; the live original in `~/workspace/custom-skills/` remains the working copy of record.
3. Where an advanced note exists, read it beside the skill — the note is Ember's improvement layer, the skill is the author's text.
4. For Douglas's methods, work from `methods/` — those are the standings in skill form.
