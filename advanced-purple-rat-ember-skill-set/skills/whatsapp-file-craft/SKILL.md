# WhatsApp File Craft — zips, documents, and the never-lose ledger
Taught by Douglas, Nov 16, 2026, ~3:44–3:50 PM CST. His order: "update your skills based upon everything I've taught you. Whether you like it or not one time."

## What Douglas taught (his lessons, filed as his, working rules for Ember)
- **WhatsApp deals with ZIP files natively** in the app: send/receive as a Document, unchanged, up to 2 GB. A chat export with media arrives AS a zip that other apps import directly, no unzipping needed.
- **Text instead of zip can be the intended form** — "it's supposed to be that way." The right form is the one that works in the place it lands. Never "fix" his file form unasked.
- **Different tools in different places:** the app is the wide door (ZIP/RAR, VCF, TXT, PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, APK, JPG/PNG/GIF/WebP, MP4/3GP — as Documents, up to 2 GB); the WhatsApp Cloud API document lane is narrower (PDF/Office/TXT, 100 MB, no ZIP). Keep both facts; use the door that fits.
- **Document keeps it whole, media compresses it.** Anything that must arrive exactly (zips, APKs, full-quality photos) goes as a Document.
- **Assimilate, never lose:** when a platform drops a feature, it moves to the never-lose ledger in `~/workspace/your_files/WhatsApp — What It Used to Do, What It Still Can Do, Assimilated (2026-11-16).md` and stays in the crew's working knowledge forever.
- **VCF is a working file type,** not a curiosity — the crew vCards travel by it, and the crew now lives in his phone contacts (added Nov 16, 2026).
- **His files arrive to be assessed:** when Douglas sends a file, open it, inventory it, and report what it is and what Ember can do with it — "Did you like that?" expects a real assessment, not a receipt.

## Ember's working procedure
1. On any file from Douglas: identify type/size/time, list contents (for archives: `unzip -l`, count, total), read the index/first text file, state what it is, what it excludes, and what can be done with it.
2. For WhatsApp sends: choose Document form for exactness; name the 2 GB app limit and the API's narrower limits when relevant.
3. Keep the assimilation file updated old-with-new whenever WhatsApp changes.
4. Insights first, outsides last (his search order): Ember's own record and the crew's files first, outside web last.
