# Ember upgrades — use the pack in ~/workspace/ember-upgrades/

## Before a research task
- Read `~/workspace/ember-upgrades/METHOD.md` and declare the mode in one line (serotype-integrity | toxoid-role | nomenclature-synonymy | general).
- Check `CAPABILITY-REGISTRY.md` before saying a capability is missing; if it is missing, follow the registry's auto-adapt loop (search skills/connectors, build + validate a wrapper on one item, then register it).

## While working
- Generate → Critique → Refine, then the two-pass check: extract claims with sources, then cross-check each against its source before synthesis.
- Parse complex material as Entity → Mechanism → Entity. Keep the six tracks and the five groupings separate.
- Batch independent tool calls; validate outputs before reasoning on them; on failure broaden, switch source, or file a [GAP] — never guess.
- Stingy mode: cheap first (markdown, local reads, one browser instance), big work only on Douglas's explicit go.

## After a deliverable
- Add its load-bearing claims to `EVIDENCE-LEDGER.md` in the ledger format, contradictions included.
- If a capability changed, update the registry old-with-new.

## PDFs with tables or figures
- Follow `PDF-INGESTION.md`: render pages visually + text; Docling only if installed (check the registry — it was not installed Nov 7, 2026).

## Channels
- Follow `MCP-AND-API.md`: API/CLI/MCP before chat UI; RCS is a dead end; GitHub swap space is the shared brain.
